## Learned User Preferences

- When building from a plan: create a feature branch, commit after verified success, merge into local `main`, then delete the feature branch and stay on `main`. Commit/merge to local `main` is fine; never push to remote `main` without express permission.
- Write GitHub README and user docs for people installing and using the app; keep agent/build internals (snapshots, grid lint, MCP, CI badges) out of the main path. README shields stay at latest-release, macOS, and license only — no CI, vanity, or AI badges.
- Do not propose Developer ID, notarization, App Store, sandbox, or SwiftLint unless Lewis changes those product goals.
- Treat MacMinion as source-available under PolyForm Noncommercial, not open source — do not suggest MIT/Apache or lists that require an OSI license.
- When driving GitHub UI for this repo, use the Safari Personal window (solaegis account); Work Safari is the Acxiom session. Cursor Computer Use needs Accessibility and Screen Recording; if those are off, drive Safari via accessibility or AppleScript instead.
- Localization v1 is app UI only (not README/docs or EsoMacMinion; agent CLI/harness stay English): English source plus German, French, Spanish, and Russian; follow macOS language by default with an optional Settings → Appearance override; use Apple String Catalogs and machine-translate for the first ship (not hand-rolled L10n tables). Keep the English README invite for native speakers to improve de/fr/es/ru wording.
- Add Apple Intelligence (on-device Foundation Models) as an AI backend beside Ollama/Claude/OpenAI; default to it on first launch only when the system model is available — do not migrate users who already saved Off or another provider.
- Prefer verifying local builds from `~/Applications` after `task build` / `task build:open` / `task build:install`; do not assume `/Applications` MacMinion matches local `main` until a release is cut.
- `task build:open` should quit any already-running MacMinion before relaunching the newly built app.

## Learned Workspace Facts

- Public repo is `solaegis/mac-minion`; docs and Sparkle feed live at `https://solaegis.github.io/mac-minion/`. Docs pages only ship when listed in `tools/build-site.py` nav (a page file alone is not enough).
- In-game companion addon is **EsoMacMinion** (`solaegis/eso-mac-minion`, `~/git/solaegis/eso-mac-minion`); reads SV global `EsoMacMinion_Data` (game file often `SavedVariables/EsoMacMinion.lua`). Do not use legacy `MacMinionCompanion` / `eso-macminion-companion` names. Treat the live SV file as read-only (copy to `/tmp` for fixtures). Companion load rules (CrossOver): never walk `_G`, nothing heavy during `USER_INTERFACE` load, wrap LAM only after activation, bookkeeping inside `pcall`. Design SoT: `docs/COMPANION-ADDON.md`. Companion lua errors older than 7 days are dropped from Problems; CompanionDataTests that assert those errors must freeze time (`companionTestNow` / `now:`), not wall-clock `Date.now`.
- Game Folder is an experimental sidebar for ESO SavedVariables, characters, problems, and space; when extending it, surface companion state from `CompanionData` and keep Problems actionable. `CompanionData.snapshot()` must pick written/env/layouts from the newest `$AccountWide` by `written` (not first block in file order) and merge errors across blocks. After Clean Up / SV-mutating actions, re-read SavedVariables so Problems does not stick on Starting…. Parsed SavedVariables trees are shared via `SVDocumentCache` (stamped LRU) across Find, Connections, character places, and the Inspector. Inspector Settings uses one-section-at-a-time Readable sheets (`ReadableSheetView` / `SVReadable.grouped`); long Inspector pages use an outline plus drill-down breadcrumbs (Inspector only, not app Settings).
- License is PolyForm Noncommercial 1.0.0 (copyright Lewis Vavasour); GitHub classifies it as Other.
- Shipping is GitHub Releases plus Sparkle 2 (EdDSA); follow `RELEASE.md`. CI signs with the MacMinion Release certificate so TCC survives updates; not Apple Developer ID and not notarized. The release workflow updates `site/appcast.xml` via a short-lived PR that waits for required `swift test`, then merges—not a direct bot push to protected `main`. Repo Actions must allow creating pull requests for that feed step; otherwise open/merge the feed branch by hand.
- GitHub About (Releases on; Packages/Deployments off) and the social-preview image have no API and are already set — do not re-upload or treat them as leftover launch work.
- SPM-only SwiftUI app (no Xcode project); macOS 26, Apple Silicon. `build.sh` must install a Contents-style `MacMinion_MacMinionKit.bundle` under `Contents/Resources` (synthesize from the kit String Catalog if needed). Kit UI strings use `Bundle.kit`, not SPM's `Bundle.module` (CI's native accessor probes the app root, which codesign rejects as unsealed contents). A missing kit bundle fails selftest titles / Find More filters. Release tags use semantic versioning (`vMAJOR.MINOR.PATCH`, e.g. `v0.6.0`); historical `v0.5` stays. A matching tag cuts a release. Local `task build` without `MACMINION_VERSION` stamps About from the latest `v*` git tag (else `0.1`); set `MACMINION_VERSION` explicitly when packaging a release. `task build:install` is an alias of `task build`.
- App store persistence is file-backed JSON under Application Support (or `APP_STORE`): `state.json`, `catalog.json`, `categories.json`, and related caches — not SwiftData or SQLite (CLAUDE.md’s “SwiftData database” line is stale). Game Folder data stays a derived in-memory view of on-disk ESO files, not a SQL/graph primary store.
- Optional support is Buy Me a Coffee via `.github/FUNDING.yml` (`buy_me_a_coffee: lewisvavasw`); the public page display name is solaegis. Do not add a BMC shield.
- r/elderscrollsonline bans anything that uses AI in any form ([wiki/rules](https://www.reddit.com/r/elderscrollsonline/wiki/rules/)). Posts, comments, screenshots, and linked copy for that sub must not mention AI, Ollama, Claude, OpenAI, or related features.
- Snapshot and selftest/verify runs need MacMinion excluded from BetterStage (or quit BetterStage); otherwise the window is stashed or resized and checks hang or miss `-min` shots.
- CI `swift test` uses the atreides self-hosted runner only for `push` to `main`; every `pull_request` (same-repo or fork) stays on GitHub-hosted `macos-26` because PR workflows come from the merge commit. Release stays GitHub-hosted. Ops notes: `docs/self-hosted-runner.md`.
